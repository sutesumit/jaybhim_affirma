Documentary Gallery Architecture and Logical Flow

This document describes the current logical flow of the documentary portfolio gallery, image modal, controller hook, and surrounding UI components. It is meant to be a companion architecture reference to the existing feature spec and a debugging guide for modal, slideshow, and URL-sync behavior.

Location: specs/features/ Scope: Documentary Gallery + Image Modal + Hook Based on current code in src/app/(pages)/documentary-portfolio/

1. High-Level System Shape

Entry Flow

documentary-portfolio/page.tsx
  -> getImageList()
  -> page-level metadata / JSON-LD
  -> <Suspense>
       -> <DocumentaryGallery images={images} />

DocumentaryGallery
  -> useDocumentaryGalleryController({ images, slideShowInterval })
  -> renders:
       PreviewImage
       GalleryControls
       ThumbnailStrip
       Dialog/DialogContent
         -> ImageModal

Current Ownership Boundaries

  • page.tsx owns server-side image loading and page shell setup.
  • DocumentaryGallery.tsx owns composition and DOM/event wiring.
  • useDocumentaryGalleryController.ts owns reducer state, slideshow behavior, and URL sync.
  • ImageModal.tsx is presentational and action-emitting.
  • dialog.tsx owns Radix dialog shell styling and shell animations.
Intent: the controller is supposed to be the single state owner for modal lifecycle, selected image, slideshow pause/resume, and URL synchronization.

2. Files and Responsibilities

File Responsibility Inbound Data Outbound Effects / Events
page.tsx Server entrypoint for documentary portfolio. getImageList(), page metadata. Passes images into DocumentaryGallery.
imageList.ts Builds GalleryImage[] from public/documentary_portfolio and metadata.json. Filesystem images + metadata map. Returns normalized image records with filename, src, alt, metadata fields.
DocumentaryGallery.tsx Composes gallery UI, binds keyboard events, bridges dialog lifecycle to controller actions. Controller outputs + images. Calls controller commands, renders dialog and modal, forwards modal prev/next handlers.
useDocumentaryGalleryController.ts Reducer-driven interaction model for gallery state, modal lifecycle, slideshow, and URL sync. images, slideShowInterval, router, search params. Dispatches state transitions, writes URL via router.replace().
GalleryControls.tsx Overlay controls for navigation, play/pause, info-card tabs. currentImage, playback state, nav callbacks, modal opener. Fires prev/next/play/modal-open UI events.
InfoCard.tsx Shows current image contextual info and the “Get a Print” action. Section id + current image data. Calls onOpenModal(data) from button click.
PreviewImage.tsx Full-bleed background image for current gallery index. Image src/alt and animation direction. Framer Motion visual transition only.
ThumbnailStrip.tsx Scrollable bottom thumbnail rail. images, currentIndex. Calls onSelect(index).
ImageModal.tsx Modal body, image viewport, metadata, share action, modal chevrons. image, direction, modal nav callbacks. Calls prev/next handlers, copies URL to clipboard, shows toast.
dialog.tsx Styled Radix dialog shell with overlay/content animations. Controlled open state from caller. Raises onOpenChange, emits CSS close/open animations.

3. Core Data Model

GalleryImage Shape

GalleryImage {
  filename: string
  src: string
  alt: string
  year: string
  caption?: string
  organization?: string
  camera?: string
  lens?: string
  exposure?: string
  focalLength?: string
  iso?: string
}

Controller State Shape

DocumentaryGalleryState {
  currentIndex: number
  direction: number
  isSlideShowPlaying: boolean
  modalPhase: "closed" | "open" | "closing"
  selectedImageId: string | null
  wasSlideShowPlaying: boolean
}
Important distinction: currentIndex is the gallery cursor. selectedImageId is the modal subject. The architecture is healthiest when those are intentionally synchronized by reducer actions, not repaired later by effects.

4. Controller Outputs

Output Meaning Used By
currentIndex Current gallery position. PreviewImage, ThumbnailStrip.
currentImage Resolved image at currentIndex. GalleryControls, PreviewImage.
direction Animation direction for gallery/modal transitions. PreviewImage, ImageModal.
isDialogOpen Whether Radix should consider the dialog open. Dialog open={...}.
modalImage Resolved image from selectedImageId. ImageModal.

shouldRenderModalContent Whether modal body should remain mounted. DocumentaryGallery conditional render.
canInteractWithGallery Whether keyboard and gallery controls should remain active. DocumentaryGallery, GalleryControls.

5. Event and Data Flow

A. Initial Page Load

  1. page.tsx calls getImageList().
  2. Images are normalized from disk and metadata JSON.
  3. DocumentaryGallery mounts with the static image array.
  4. The controller reads useSearchParams().
  5. If ?image=filename exists and maps to a known image, reducer dispatches SYNC_FROM_URL.
  6. State transitions to modalPhase = "open", selected image set, slideshow paused.

B. Passive Gallery Playback

  1. If isSlideShowPlaying is true, the controller interval dispatches GO_NEXT.
  2. The reducer increments currentIndex and sets direction = 1.
  3. DocumentaryGallery re-renders with new currentImage.
  4. PreviewImage animates the background image swap.
  5. ThumbnailStrip scroll-centers the active thumbnail.

C. Open Modal from Info Card

GalleryControls
  -> InfoCard
     -> "Get a Print" button
        -> onOpenModal(currentImage)
           -> controller.openImage(image)
              -> dispatch OPEN(imageId, index)
                 -> modalPhase = "open"
                 -> selectedImageId = imageId
                 -> currentIndex = index
                 -> wasSlideShowPlaying = current isSlideShowPlaying
                 -> isSlideShowPlaying = false

D. Dialog Rendering

  1. DocumentaryGallery passes open={isDialogOpen} to Radix.
  2. If shouldRenderModalContent is true and modalImage exists, it renders ImageModal.
  3. ImageModal animates only its internal image and metadata changes.
  4. dialog.tsx owns shell animation for overlay and dialog container.

E. Modal Next / Prev

  1. User clicks left/right chevrons in ImageModal.
  2. The modal calls goPrevInModal() or goNextInModal().
  3. Controller dispatches MODAL_PREV or MODAL_NEXT.
  4. The reducer updates:
    • direction
    • currentIndex
    • selectedImageId
  5. Background preview and modal image both point at the new image.
  6. State-to-URL effect updates ?image=filename.

F. Close Modal

User close intent
  -> Radix onOpenChange(false)
     -> controller.requestClose()
        -> dispatch REQUEST_CLOSE
           -> modalPhase = "closing"

Derived effects:
  isDialogOpen = false
  shouldRenderModalContent = true

Result:
  -> Radix shell animates closed
  -> modal body can stay rendered during teardown

When DialogContent animation ends:
  -> completeClose()
     -> dispatch CLOSE_COMPLETE
        -> modalPhase = "closed"
        -> selectedImageId = null
        -> isSlideShowPlaying = wasSlideShowPlaying

6. URL Synchronization Flow

State → URL

  1. The controller computes desiredImageId.
  2. If modalPhase === "open", the desired URL contains the selected image.
  3. If phase is not open, the desired URL clears image.
  4. replaceImageParam() calls router.replace() and sets ignoreNextSearchParamRef.

URL → State

  1. A searchParams change triggers the sync effect.
  2. If the change was initiated locally, ignoreNextSearchParamRef skips one sync pass.
  3. Otherwise the controller dispatches SYNC_FROM_URL with:
    • imageId
    • resolved image index or null
  4. The reducer decides whether to open, start closing, or ignore the URL event.
Architectural tension: URL sync is intentionally adapter logic, but it still participates in lifecycle transitions. This means modal bugs often come from disagreements between modalPhase, selectedImageId, and what searchParams currently says.

7. Interaction Matrix

User Action Primary Handler Reducer Action(s) Visual Result
Play / Pause button GalleryControls -> onTogglePlay TOGGLE_SLIDESHOW Background autoplay starts or stops.
Gallery prev / next controls GalleryControls -> goPrev/goNext GO_PREV, GO_NEXT Background preview and current info-card content change.
Thumbnail click ThumbnailStrip -> onSelect(index) SELECT_INDEX Background preview jumps to clicked image.
Get a Print InfoCard -> onOpenModal(currentImage) OPEN Dialog opens, slideshow pauses, URL gains ?image=....
Modal chevrons ImageModal -> onPrev/onNext MODAL_PREV, MODAL_NEXT Modal image and gallery cursor advance together.
Modal close / overlay / Escape Dialog onOpenChange(false) REQUEST_CLOSE, then CLOSE_COMPLETE Dialog closes, URL clears, slideshow may resume.
Share button ImageModal.handleShare() None in reducer Clipboard write + toast feedback.

8. Key Invariants

Invariant 1

When modalPhase === "closed", selectedImageId should be null.

Invariant 2

When modalPhase === "open", the dialog should be controlled open and the selected image should be present.

Invariant 3

When modalPhase === "closing", the dialog shell should be closing but modal content may still be retained for teardown.

Invariant 4

Modal navigation should update selectedImageId and currentIndex together in one reducer step.

Invariant 5

URL sync should represent controller state, not independently fight controller state during close/open transitions.

9. Current Risk Areas

Close lifecycle relies on animation completion.

CLOSE_COMPLETE currently depends on a dialog content animation-end callback. If that shell animation does not fire, the controller can remain stuck in closing.

URL events during closing are intentionally ignored.

That avoids reopen races, but it also means a history change that happens during teardown may need an explicit replay or follow-up sync once the modal is fully closed.

Gallery and modal are synchronized by policy, not by visual isolation.

Right now modal next/prev moves both the modal subject and gallery cursor. That is fine if intended, but it means the background is not a frozen snapshot while the modal is open.

10. Recommended Reading Order for Future Debugging

  1. Start with specs/features/documentary-portfolio-image-modal.md for feature intent.
  2. Read page.tsx and imageList.ts to understand how the gallery gets its data.
  3. Read useDocumentaryGalleryController.ts top to bottom:
    • state shape
    • action types
    • reducer transitions
    • URL sync effects
  4. Read DocumentaryGallery.tsx to see how controller state maps into UI.
  5. Read ImageModal.tsx and dialog.tsx last to separate presentational animation from state logic.
