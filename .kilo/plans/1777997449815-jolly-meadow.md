# Plan: Align ImageModal Styling with ConfirmDialog

## Goal

Restructure `ImageModal.tsx` so its layout and visual structure mirror the `ConfirmDialog` component (`src/components/ui/confirm-dialog.tsx`), **without** applying the destructive (red) color scheme. The ImageModal should keep its existing default blue/white theme.

## Reference: ConfirmDialog structure

```
DialogContent (max-w-sm)
  DialogHeader
    DialogTitle (cn: red only when variant="destructive")
  DialogDescription (optional)
  DialogFooter
    button (Cancel)  — button-style
    button (Confirm) — button-style, red hover only when destructive
```

Key visual traits of ConfirmDialog:
- `DialogHeader` + `DialogTitle` at top (centered, uppercase, border-bottom)
- `DialogDescription` for body text (applies `px-8 pt-2`)
- `DialogFooter` at bottom with flex row
- Buttons use `button-style` class

## Current ImageModal structure

```
<div className="flex flex-col items-center max-h-[90vh] overflow-y-auto">
  <div className="inline-title-style">Image Details</div>
  <div className="px-4 pb-4 flex flex-col items-center w-full">
    <div className="relative w-full h-[50vh]...">  ← image container
    <div className="w-full max-w-2xl...">          ← metadata
    <div className="w-full flex flex-wrap...">     ← action buttons
  </div>
</div>
```

## Changes required

### 1. Replace title div with DialogHeader + DialogTitle

**File:** `src/app/(pages)/documentary-portfolio/components/ImageModal/ImageModal.tsx`

- Remove `<div className="inline-title-style">Image Details</div>`
- Import `DialogHeader`, `DialogTitle` from `@/components/ui/dialog`
- Wrap "Image Details" text in `<DialogHeader><DialogTitle>Image Details</DialogTitle></DialogHeader>`

### 2. Wrap metadata section in a descriptive container

- Import `DialogDescription` from `@/components/ui/dialog`
- The existing metadata DIV (`<div className="w-full max-w-2xl my-2 space-y-2">`) can be kept as-is or simplified — it already handles caption + metadata fields. No need to wrap in `DialogDescription` since the metadata contains structured content, but aligning padding via the parent container is needed.

### 3. Replace action buttons div with DialogFooter

**File:** `ImageModal.tsx`

- Import `DialogFooter` from `@/components/ui/dialog`
- Replace the action buttons wrapper `<div className="w-full flex flex-wrap items-center justify-center gap-2 mt-2">` with `<DialogFooter>`
- The footer already applies `flex px-8 pb-4 flex-col-reverse sm:flex-row sm:justify-end sm:space-x-2` which will need adjustment for centered action buttons. The existing buttons should remain but get restructured within `DialogFooter`.

### 4. Adjust DialogFooter styling for action buttons

The default `DialogFooter` aligns buttons to the right (`sm:justify-end`). The ImageModal needs buttons centered. We'll override with `className="justify-center"` on `DialogFooter` and adjust the image+metadata container padding to match `DialogDescription`'s `px-8` convention.

### 5. Tune padding/consistency

- The `DialogHeader` / `DialogTitle` already provides consistent top padding via `px-2 py-2`.
- The `DialogDescription` uses `px-8 pt-2`.
- The image container currently has `px-4` (parent) — should align to `px-8` for consistency with ConfirmDialog.
- The outer `<div className="flex flex-col items-center max-h-[90vh] overflow-y-auto">` can be simplified to just `flex flex-col` since `DialogContent` provides the `w-full` and max-width.

## Risks

- `DialogFooter`'s default `sm:flex-row-reverse` layout may flip button order. Need to verify the ordering is natural (Buy, Like, Share left to right).
- `DialogTitle` from ConfirmDialog uses `DialogPrimitive.Title` which sets an `id` for aria — this may interact with the current `VisuallyHidden.Root` wrapper in `DocumentaryGallery`. Need to decide: either remove the VisuallyHidden title from DocumentaryGallery (since ImageModal now provides its own) or add `aria-labelledby` appropriately.
- Image height container (`h-[50vh] sm:h-[55vh] md:h-[60vh]`) may need adjustment inside the tighter `DialogFooter` layout constraint.
